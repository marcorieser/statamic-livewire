Named, always, lazy (with a placeholder), and looped islands — each updates independently without re-rendering the rest of the component. The addon's livewire:island tag piggybacks Livewire's own island pipeline (Blade's @island/@endisland directives), so island content sees the same scope either way: the component's own public and computed properties, not the surrounding template's — a loop's per-item value isn't available inside an island's own content in Antlers or Blade.

The looped island's name is missing here on purpose — dynamic names resolve eagerly in Antlers (the tag's name param is a plain resolved string by the time it reaches Livewire), but Blade's @island recompiles its whole directive — including the name argument — in the island's own isolated file on every render, with no access to the enclosing loop. That's not a captured-scope feature, just how the two template engines evaluate tag arguments.
